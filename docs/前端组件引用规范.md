# 前端组件引用与解析规范

> 适用范围：`src/**` 下所有 `.vue` 文件
> 目的：避免出现 `[Vue warn]: Failed to resolve component: xxx` 运行时告警
> 校验日期：2026-10-30（已全量扫描 9 个视图 + 20 个组件）

## 一、问题背景

本项目曾出现如下告警：

```
[Vue warn]: Failed to resolve component: ListPager
If this is a native custom element, make sure to exclude it from component
resolution via compilerOptions.isCustomElement.
  at <UserListView ...>
```

**根因**：`UserListView.vue` 的模板中使用了 `<ListPager>`，但 `<script setup>` 中没有 `import` 该组件。
Vue 的 `<script setup>` 是「按需导入」机制——模板里用到的自定义组件，必须在脚本中显式 `import`，否则运行时无法解析，每次重渲染都会重复告警。

## 二、组件解析三分类（核心规则）

模板中的标签按以下三类判断是否需要 `import`：

| 分类 | 是否需 import | 说明 |
|---|---|---|
| **自定义组件**（`src/components/**`） | ✅ 必须 | 每个使用处都要 `import Xxx from '@/components/...'` 或相对路径 |
| **全局注册的 Element Plus 组件** | ❌ 免 import | 已在 `main.ts` 中 `app.use()`，模板可直接写 `<el-*>` |
| **Vue / vue-router 内置组件** | ❌ 免 import | 见下表 |

### 免 import 的内置组件清单

| 来源 | 组件 |
|---|---|
| Vue 内置 | `<Transition>` `<TransitionGroup>` `<Teleport>` `<component>` `<slot>` `<KeepAlive>` `<Suspense>` |
| vue-router 内置 | `<router-view>` `<router-link>` |

## 五、检测规范（后续代码调整必须执行）

### 5.1 新增 / 修改 `.vue` 时的必查项

1. **模板 → import 逐标签核对**：模板里出现的每个 PascalCase（或非 `el-` 前缀、非 HTML 标签）的自定义组件标签，确认 `<script setup>` 中有对应 `import`。
2. **import 路径真实存在**：`import Xxx from '@/components/Yyy.vue'` 的路径必须能对应到真实文件，否则构建报错。
3. **命名一致**：`import` 的默认导出名与模板标签名一致（统一 PascalCase，如 `ListPager`）。
4. **不要重复 import 全局组件**：`el-*` 已全局注册的组件无需再 import，避免冗余。
5. **自引用 / 循环引用**：组件之间不要形成循环 import（如 A import B 且 B import A）。

### 5.2 标准自查清单（逐项打勾）

- [ ] 模板中的自定义组件均已 `import`
- [ ] 无「import 了但文件不存在」的引用
- [ ] 无「模板用了但没 import」的标签
- [ ] `el-*` 组件未重复 import
- [ ] 组件命名（import 名 ↔ 模板标签名）一致

### 5.3 排查方法（发现问题时）

当控制台出现 `Failed to resolve component: Xxx` 时：

1. 定位告警中 `at <XxxView>` 指向的 `.vue` 文件；
2. 打开该文件，在模板中搜索组件标签 `Xxx`（或 `<xxx` kebab-case 形式）；
3. 检查 `<script setup>` 顶部是否缺少 `import Xxx from '...'`；
4. 若缺，按第三节/第四节路径补齐 import（参考同目录其他文件，如 `AlarmListView.vue` 第 8 行的写法）。

### 5.4 红线规则

- **禁止**在模板中使用未 `import` 的自定义组件。
- **禁止** import 不存在的组件路径。
- **禁止**对已全局注册的 `el-*` 组件再 `import`（除非确实需要局部覆盖）。
